# 1. Contexto de la aplicación

## 1.1. Mundo real del problema

Pokémon Store surge como una propuesta de tienda online centrada en los Pokémon. La idea es ofrecer un espacio en el que los usuarios puedan consultar los Pokémon disponibles y, como objetivo de la aplicación, adquirir aquellos que les interesen.

El proyecto se desarrolla en el contexto del segundo curso de Desarrollo de Aplicaciones Web (DAW), por lo que también nos permite poner en práctica los conocimientos adquiridos durante el curso y trabajar con una aplicación que vamos construyendo progresivamente.

## 1.2. Aplicaciones existentes

Existen varias aplicaciones relacionadas relacionadas con la gestion de Pokémon. No obstante, esta aplicación está basada en un proyecto de clase.

Pokémon Store plantea una propuesta centrada en la gestión de un catálogo de Pokémon.

## 1.3. Propuesta de nuestra aplicación

Nuestra aplicación pretende ofrecer una plataforma en la que trabajar con un catálogo de Pokémon, permitiendo realizar diferentes operaciones sobre ellos.

Actualmente estamos desarrollando las siguientes operaciones:

- Consultar los Pokémon disponibles.
- Crear nuevos Pokémon.
- Modificar la información de Pokémon existentes.
- Eliminar Pokémon del catálogo.

Estas funcionalidades constituyen la base actual de la aplicación. A partir de ellas podremos seguir ampliando el proyecto conforme avancemos en su desarrollo.

## 1.4. Casos de uso

Los casos de uso representan las operaciones que los actores externos pueden realizar sobre la aplicación.

| Actor | Caso de uso | Descripción |
|---|---|---|
| Usuario | Consultar Pokémon | Permite consultar los Pokémon del catálogo. |
| Usuario | Crear Pokémon | Permite registrar un nuevo Pokémon. |
| Usuario | Modificar Pokémon | Permite actualizar la información de un Pokémon. |
| Usuario | Eliminar Pokémon | Permite eliminar un Pokémon del catálogo. |

## 1.5. Requisitos funcionales y no funcionales

### 1.5.1. Requisitos funcionales

Los requisitos funcionales describen las operaciones que debe permitir realizar la aplicación.

| Identificador | Requisito |
|---|---|
| RF01 | La aplicación permitirá consultar los Pokémon del catálogo. |
| RF02 | La aplicación permitirá crear nuevos Pokémon. |
| RF03 | La aplicación permitirá modificar la información de los Pokémon existentes. |
| RF04 | La aplicación permitirá eliminar Pokémon del catálogo. |

### 1.5.2. Requisitos no funcionales

Los requisitos no funcionales describen características y condiciones que debe cumplir la aplicación.

| Identificador | Requisito |
|---|---|
| RNF01 | El código deberá estar organizado de forma clara y estructurada. |
| RNF02 | La aplicación deberá mantener una separación adecuada de responsabilidades. |
| RNF03 | La estructura del proyecto deberá facilitar la incorporación de nuevas funcionalidades. |
